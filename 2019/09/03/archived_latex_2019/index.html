LaTeX 排版 01：从最小文档到多文件工程

文章目录

写一份实验报告时，真正需要反复修改的是内容、章节关系和数据。如果每次增加一节都要手工改目录、调整页码、重新检查“见第三节”，文档越长，维护成本就越高。LaTeX 适合把这些关系写进源文件，再由排版系统统一生成 PDF。

这篇从一份能编译的中文文档开始，逐步加入章节、页面样式和多文件组织。目标是能够独立维护一份小型技术报告，并读懂大多数模板的骨架。完整学习顺序见学习指南，各篇集中在LaTeX 排版分类。

本文保留 2019 年旧笔记的地址，并在 2026 年重新整理。旧文中的图片、封面、表格宽度、跨行跨列和彩色表格，归入图表与版式篇；公式、交叉引用和参考文献，归入公式与引用篇。这里集中解决“文档怎样组织、怎样编译、出错怎样定位”。

1. 先区分编辑器、发行版、引擎和宏包

“我装了一个 LaTeX 编辑器，为什么还不能编译？”通常是把写文件的工具与处理文件的工具混在一起了。

层次 负责什么 常见例子
编辑器 编辑 .tex、展示日志、调用构建命令 TeXstudio、VS Code
发行版 提供引擎、宏包、字体与辅助程序 TeX Live、MiKTeX
引擎与格式 读取源文件并完成排版 使用 LaTeX 格式的 XeTeX，即 XeLaTeX
文档类 决定文章、报告、书籍的基本结构 article、report、book
宏包 添加中文、插图、公式、页眉等能力 ctex、graphicx、amsmath
构建工具 判断需要调用哪些程序、是否需要再编译 latexmk

MiKTeX 和 TeX Live 都是发行版，不能仅凭安装体积判断哪个“正确”。MiKTeX 提供缺失宏包的按需安装；是否允许自动安装，则取决于实际配置。项目中更重要的是明确编译引擎、宏包和字体，让另一台机器也能复现。MiKTeX 项目说明

本系列统一使用 UTF-8 源文件、XeLaTeX、CTeX 中文文档类。CTeX 宏集提供 ctexart、ctexrep、ctexbook 等类，在标准文档结构上加入中文支持；它与早年的“CTeX 套装”不是同一概念。示例显式选择 Fandol 字体，减少不同操作系统默认字体造成的差异。CTeX 手册第 2、4 节

3. 正文：段落、特殊字符和列表

段落与换行

源文件中的一个空行表示另起一段。为了便于编辑而在一段中按回车换行，通常仍是同一段；连续输入许多空格，也不会产生同样宽度的排版空白。中文相邻字符间的空白还会受到中文处理规则影响，所以不要靠源代码缩进来控制版面。

\\ 用于需要明确换行的地方，例如表格行尾或某些对齐环境；不要用 \\ \\ 代替段落间距。段落的首行缩进由 \parindent 控制，段间距离由 \parskip 控制，它们解决的是不同问题。CTeX 已提供中文段落设置，先观察默认效果，再按报告要求调整。临时取消某一段缩进可用 \noindent。

4. 导言区怎样保持清楚

模板容易变复杂，是因为每遇到一个问题就追加一段配置，却没有记录每段解决什么。建议将导言区按职责分组：文档类、页面布局、图表与数学、链接、少量自定义命令。每新增一个宏包，先确认当前文档类有没有提供同类功能。

正文用 \projectname{} 输出项目名，用 \term{坐标变换} 标记重要术语。空花括号可以结束命令名，也能在随后需要英文空格时保留合适的边界。若以后调整项目名称或术语样式，修改一处定义即可。

\newcommand 在同名命令已存在时会报错，有助于发现冲突；需要有意修改已有命令时才用 \renewcommand。\let 是复制当时的命令含义，属于更底层的工具，不是“重置编号”的通用方法。不要把包含 verbatim 或 lstlisting 的整段内容直接塞进普通 \newcommand 的参数里，再把报错简单归因于宏包冲突；逐字读取有特殊规则。

普通文档中，把 \usepackage 写在文档类之后。等到需要把共享样式做成 .sty 或 .cls 时，再学习 \RequirePackage、\ProvidesPackage、\ProvidesClass、\NeedsTeXFormat；这些命令分别有包、类和格式声明的职责，没必要在第一份报告里复制一套模板作者代码。LaTeX 类与宏包作者指南

input、include 和 includeonly 的差别

命令 主要行为 适合的用途
\input{sections/method} 在当前位置读取文件，不主动分页 小节、表格片段、共享配置
\include{chapters/method} 在边界执行清页，并为该单元维护辅助文件；不能嵌套 本来就从新页开始的章
\includeonly{chapters/method} 在导言区指定本次处理哪些 include 单元 长文档中临时只排某几章

\include 不会自动检测哪一章发生变化，然后只编译那一章。没有 includeonly 时，各个 include 单元仍会按顺序处理；构建工具判断是否重跑，与文档中跳过哪些章，是两个机制。LaTeX 文件读取实现与说明

7. 页面布局与页眉页脚

geometry 处理纸张、正文区和页边距等尺寸关系，fancyhdr 处理页眉页脚内容。把两者分开理解，能避免“改了页眉，正文却挤到下一页”时无从检查。

includeheadfoot 将页眉页脚纳入版面尺寸计算；headheight 给页眉留出高度。它不保证任意字体或多行页眉都能放下：如果日志提示页眉高度不足，应按实际内容调整，并重新观察正文区。geometry 手册

9. 编译出错时，先找到第一个真正的原因

先确认三个输入：正在编译哪个主文件、调用哪个引擎、从哪个工作目录运行。误编译子文件、用错引擎和相对路径错误，常常比复杂的宏包冲突更常见。

使用前面的 -file-line-error -halt-on-error 选项，日志会更容易定位到文件和行号。修正第一个错误后再编译，不要从最后一个错误倒着猜：缺失一个花括号可能制造出后面几十条连锁报错。

日志现象 优先检查什么 验证方式
Undefined control sequence 拼写、缺少宏包、命令是否属于当前文档类 缩减到仅保留该命令的最小文件
File ... not found 路径、大小写、工作目录、宏包是否安装 区分缺的是项目图片还是 .sty
Missing $ inserted 正文里出现数学语法，如未转义的 _ 看报错位置及其上一行
Runaway argument 参数未闭合、环境边界或逐字代码误用 检查最近增加的 {} 与 begin/end
Overfull \hbox 长公式、长路径、固定宽度内容超出行宽 打开 PDF，找到实际越界位置
引用显示 ?? 标签拼写、编译是否完成、引用对象是否存在 让构建工具完成必要轮次

出现 PDF 不代表排版完成：编辑器可能展示上一次成功的文件，也可能在遇错后继续生成不完整内容。核对文件更新时间、进程退出码和日志，再检查 PDF 中的中文、目录、页码及图表。

若错误只在大模板里出现，把相关正文复制到最小文件，按需加入宏包和设置，直到复现问题。这样找到的是“哪组条件触发错误”，而不是在整份模板里盲目删改。只有确认辅助文件残留影响结果时，才清理辅助文件后重建；源文件、图片与 .bib 不属于清理对象。

10. 做一份可维护的两页报告

练习从上面的最小文件开始，不必一次加入所有宏包。每完成一步就编译并观察变化：

  1. 写“实验目的、方法、结果”三个节，加入一个三级标题。目录只展示到二级，三级标题仍带编号。
  2. 加入一个步骤列表、一个脚注，以及包含 %、_ 的普通文字，确认特殊字符没有吞掉正文。
  3. 将三节分别放进 sections/，主文件只安排顺序。修改子文件，确认构建入口始终是主文件。
  4. 给报告加短页眉和居中页码；刻意写长一点的页眉，观察是否出现高度或重叠问题，然后调整。
  5. 在一个副本中把 section 拼错，练习用日志找到文件和行号；修复后检查退出码和 PDF 更新时间。
  6. 另建 ctexbook 练习，比较 input 与 include 在分页上的差别，再验证 includeonly 生成的 PDF 确实省略其他章。

完成后应能解释：源文件换行为什么不一定换段、目录为什么需要辅助文件、编号深度为什么不同于目录深度、子文件为何不重复写文档类、局部编译为什么不能直接作为完整交付物。
