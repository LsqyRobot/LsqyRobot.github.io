Descriptor-selected launch

选择场景并启动完整控制图

入口会按场景描述加载 Go2 xacro、ros2_control hardware、两个控制器、Lifecycle supervisor、RViz2、noVNC 与只读诊断服务。

ROS2_CONTROL_SCENARIO=go2_mock ./bin/site.sh ros2-serve 4000

集成方式：新增机器人时提供一份受校验的 scenario YAML、对应 xacro / URDF 和控制器参数；接真实硬件或仿真时，把 mock_components/GenericSystem 替换为实现 ros2_control 接口的 hardware plugin。上层 Controller Manager、Lifecycle 状态约束与观察链路可以继续复用。

Integration slots

每一层都有明确的替换边界

SCENARIO

描述文件选择

go2_mock.yaml 固定模型、关节顺序、限制、控制器与命名空间，避免散落在启动脚本中。

HARDWARE

SystemInterface 插件

当前 GenericSystem 只做理想状态回显；后续可接 Gazebo、MuJoCo adapter 或实体硬件实现。

CONTROL

Controller Manager

控制器通过标准接口申领硬件资源；Lifecycle supervisor 只通过管理服务切换其状态。

OBSERVABILITY

RSP / TF / RViz2

Robot State Publisher 消费 broadcaster 输出并生成 TF；可选 RViz2 + noVNC、SSH -Y / XQuartz、Foxglove bridge 或 rosbag / URDF 静态播放作为观察端。

RECOVERY

STANDBY / FAULT

停用时释放命令接口；watchdog 触发故障锁存，reset 后仍需显式 activate 才恢复。

Runtime boundary

能证明什么，以及不能证明什么

本地已观察

标准 Controller Manager 管理 12 个 position command interfaces，两个控制器状态、Lifecycle 状态与 Go2 RViz2 画面来自同一容器内 ROS 图。

仍不在结论内

GenericSystem 不是接触动力学或真实执行器；GPU 加速、真实相机、串口 / USB、实体 Go2 DDS、跨机器及公网访问也未由本页验证。

终端写入边界

/workspace 是宿主仓库的读写 bind mount，文件修改会持久化；容器根文件系统只读，且没有 Docker socket。

网络边界

:6080、:7681、:9090 只绑定回环地址，不应反向代理到局域网或公网。
