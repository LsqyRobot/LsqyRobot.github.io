为什么重新整理这份笔记

以前的 Vim 笔记是边学边记的：寄存器在一篇、宏在另一篇，搜索、分屏和格式化又散落在几十条技巧里。单条命令虽然能查到，真正编辑时却很难回答两个问题：这个命令适合什么场景，以及它为什么能和别的命令组合？

这次把 2019、2020、2024 年的通用笔记和寄存器专文合并为一条学习主线，并纠正其中已经过时或不准确的内容。重点不是背快捷键，而是建立一套可以迁移到代码、配置文件和普通文本的编辑方法。

先记住一句话：

Vim 的核心不是“快捷键很多”，而是用“操作符 + 范围 + 重复”描述一次编辑。

如果只想快速开始，可依次阅读“编辑语言 → 寄存器 → 批量修改 → 工程导航”；每章末尾都可以直接在临时文件里练习。

想解决的问题 首选工具 典型命令
改一个有边界的对象 操作符 + 文本对象 ciw、di"、yap
重复刚才的修改 点命令 .
保护已经复制的内容 专用寄存器 "0p、"_d
对很多行做同一种动作 :normal :%normal! A;
重复一串依赖上下文的动作 宏 qa…q、@a、@@
跨文件查找并逐项处理 quickfix :vimgrep、:cnext
把文本交给系统命令 filter / Shell :%!sort -u

1. 模式不是门槛，而是在选择“接下来要表达什么”

Vim 最常用的四种模式分别承担不同角色：

模式 用途 常用入口 返回普通模式
普通模式 Normal 移动、删除、复制、组合命令 启动 Vim 后默认进入 已在其中
插入模式 Insert 输入新文字 i、a、o、O <Esc> 或 <C-[>
可视模式 Visual 先选择范围，再操作 v、V、<C-v> <Esc>
命令行模式 Command-line 保存、替换、搜索、批处理 :、/、? <Esc>

不要长时间停留在插入模式里寻找方向键。完成一小段输入后回到普通模式，下一步便可以继续用“动作”表达意图。

几个入口的区别很实用：

  • i 在光标前插入，a 在光标后插入；
  • o 在下方新建一行，O 在上方新建一行；
  • gi 回到上次离开插入模式的位置继续输入；
  • 插入模式中的 <C-o> 可以临时执行一次普通模式命令，执行后自动回到插入模式。

保存和退出只需先掌握这一组：

命令 含义
:w 保存当前缓冲区
:q 关闭当前窗口；有未保存修改时会拒绝
:wq 或 ZZ 保存并退出
:q! 或 ZQ 放弃当前修改并退出

这里的“窗口”和“文件”不是同一个概念，后文会专门说明。

插入模式也有不依赖插件的补全

Vim 自带的补全足以处理许多轻量场景。进入插入模式后：

命令 补全来源
<C-n> / <C-p> 当前补全来源中的下一个 / 上一个候选
<C-x><C-f> 文件名
<C-x><C-l> 整行
<C-x><C-]> tags
<C-x><C-o> 当前文件类型的 omni completion；需要相应 omnifunc

补全菜单出现后可用 <C-n>、<C-p> 选择，<C-y> 接受，<C-e> 取消。LSP 或补全插件可以提供更丰富的数据源，但这些内置按键仍有助于理解补全菜单的基本行为。

2. 把命令看成一门编辑语言

普通模式下最有价值的结构是：

常用操作符只有几个：

操作符 含义 示例
d 删除并写入寄存器 dw 删除到下一个单词
c 修改：先删除，再进入插入模式 ciw 修改当前单词
y 复制（yank） yap 复制当前段落
> / < 增加 / 减少缩进 >ip 缩进当前段落

gq 按 textwidth 格式化文本 gqap 格式化当前段落

动作描述“走到哪里”，例如 w 到下一个词、$ 到行尾、} 到下一段。文本对象描述“这个结构是什么”：

文本对象 范围 常见组合
iw / aw 单词内部 / 单词及周围空白 ciw、daw
i" / a" 双引号内部 / 连同双引号 di"、ya"
i( / a( 圆括号内部 / 连同圆括号 ci(、ya(
it / at HTML/XML 标签内部 / 连同标签 cit、dat
ip / ap 段落内部 / 连同周围空行 gqip、yap

i 可以理解成 inside，a 可以理解成 around。光标只要位于对象内部，通常不必先移动到对象开头。

3. 移动、搜索和跳转：按目标尺度选择命令

不要把所有移动都压在 hjkl 上。文本越大，越应该使用更大尺度的动作。

行内和结构移动

目标 命令
行首 / 第一个非空字符 / 行尾 0 / ^ / $
下一个词首 / 上一个词首 / 当前或下一个词尾 w / b / e
本行下一个字符 x 的位置 / 前一格 fx / tx

上一个 / 下一个段落 { / }

4. 寄存器：解决“刚复制的内容为什么被覆盖了”

Vim 的复制、删除和修改都会与寄存器交互。p 默认读取无名寄存器，因此下面的操作经常带来意外：

  1. yy 复制一行；
  2. dd 删除另一行；
  3. p 粘贴时得到刚删除的行，而不是先前复制的行。

这是寄存器设计的结果，不是复制失败。yy 同时更新无名寄存器和复制专用寄存器 0，随后的 dd 会覆盖无名寄存器，但不会覆盖 0，所以此时用 "0p 即可取回最近一次未显式指定寄存器的 yank。

动态图 2：p 读取无名寄存器；"0p 明确读取最近一次 yank。

实用寄存器速查表

寄存器 用途 示例
" 无名寄存器，默认被复制、删除和修改使用 p 等价于 ""p
0 最近一次未显式指定其他寄存器的 yank "0p
1 至 9 最近几次行删除或较大删除的历史队列 "2p
- 最近一次小于一行的删除 "-p
a 至 z 有名寄存器；写入时用大写名称表示追加 "ayiw、"Ayiw
_ 黑洞寄存器，丢弃删除内容 "_dd
+ / * 系统剪贴板 / 选择缓冲区，具体映射因平台而异 "+y、"+p
: / . / % 最近 Ex 命令 / 最近插入文本 / 当前文件名 插入模式中 <C-r>%
= 表达式寄存器 插入模式中 <C-r>=2+3<CR>
/ 最近一次搜索模式 :let @/ = '' 清空它

同一普通模式动作应用到每行 :normal! 每行可从相同初始条件开始

目标来自跨文件搜索或编译结果 quickfix + :cdo 已经有一组位置列表

缩进与文本格式化不是一回事

现代终端通常支持 bracketed paste，Vim 会识别一次外部粘贴的边界。旧笔记里把 :set paste 当成默认步骤已经不合适；只有在终端或旧版 Vim 无法正确处理粘贴时，才把它作为兼容排查手段，并在完成后立刻 :set nopaste。

7. Buffer、Window、Tab 分别是什么

很多“退出后文件怎么还在”“分屏为什么切不动”的困惑，都源于把三层对象混在一起：

对象 它代表什么 常用命令
Buffer 文件或临时文本在内存中的内容 :ls、:buffer、:bnext、:bdelete
Window 显示某个 buffer 的视口 :split、:vsplit、:close
Tab page 一组窗口布局 :tabnew、gt、gT

一个 buffer 可以同时显示在多个 window 中；关闭 window 不一定卸载 buffer；Vim 的 tab 更像“工作区布局”，不必把每个文件都放进一个 tab。

场景四：把一列名字变成 Markdown 任务项

在第一行录制一个“移到行首 → 插入 - [ ] → 移到下一行”的宏，然后用计数执行。任务需要多个动作且每行结构一致，宏比复杂替换更直观。

场景五：逐个修复项目里的废弃接口

先用 :vimgrep 或 :grep 建立 quickfix 列表，用 :cnext 查看上下文；确认变化可机械执行后，再考虑 :cdo。搜索列表与编辑动作分开，回退和复核都更容易。

11. 一次 30 分钟的练习路线

不要在真实项目里第一次尝试宏。创建一个临时文件，分四轮练习：

  1. 前 5 分钟：移动与对象。 练 w/b/e、f/;、%、ciw、di"、yap。
  2. 接着 8 分钟：搜索与重复。 用 /、n/N 找目标，完成一次修改，再用 . 复用；用 u 和 <C-r> 往返观察撤销树。
  3. 接着 8 分钟：寄存器。 依次执行 yy、dd、p、u、"0p，打开 :registers 对照每一步。
  4. 最后 9 分钟：批处理。 用 :%normal! A; 处理多行并撤销；再录一个只处理一行的宏，用 3@a 执行。

第二天在真实工作中，只要求自己识别一次“这里可以用文本对象”以及一次“这里可以用点命令”。形成场景联想，比一天背完一张快捷键表更有效。

12. 最小速查表与常见误区

最后再纠正几条很容易从旧资料中继承的误解：

  • zo 打开折叠，zc 关闭折叠；
  • G 跳到文件末尾，>G 或 =G 才是带范围的缩进操作；
  • . 重复最近修改，@@ 重复最近宏；
  • p 读取无名寄存器，不天然等于系统剪贴板；
  • buffer 是内容，window 是视口，tab page 是窗口布局；
  • :normal! 中的 ! 用来跳过自定义映射，适合可复现的批处理；
  • :set paste 是兼容排查手段，不应成为现代终端下的常驻设置；
  • Vim 内置加密不适合替代密码管理器、磁盘加密或可靠的 secrets 管理。
