为什么要学这一部分

平时把 Vim 当作编辑器使用时，很容易形成这样的习惯：退出 Vim，执行一条 Shell 命令，再重新打开文件。实际上，Vim 和 Shell 之间有多种协作方式。学会后，可以在不丢失当前缓冲区、光标位置、窗口布局和撤销历史的情况下，临时回到 Shell，或者直接让外部命令处理当前文本。

这一部分最值得先掌握的不是大量命令，而是三个层次：

  1. 暂时离开 Vim，再回到原来的编辑现场；
  2. 在 Vim 内执行一条或一组 Shell 命令；
  3. 把文本送给外部命令处理，再把结果带回 Vim。

Windows、PowerShell 与 WSL 的差异

Ctrl-Z、jobs、fg 和 bg 这一套来自 Unix Shell 的作业控制。在 Linux、macOS、WSL 中的 Bash/Zsh 里通常可以直接使用；在原生 PowerShell 或 cmd.exe 中，不要假设它有完全相同的行为。

  • 我要回到原 Shell 吗？用 Ctrl-Z，再用 fg；
  • 我要把输出放进文章吗？用 :read !；
  • 我要转换一段文本吗？用范围加 !；
  • 这是持续运行的交互任务吗？用 :terminal 或 tmux。

最小速查表

常见误区

  1. 把暂停当成后台运行：Ctrl-Z 后 Vim 是停止状态，通常用 fg 恢复。
  2. 用 bg 恢复交互式 Vim：它仍需要终端输入，常会再次停止。
  3. 认为暂停后可以安全关闭终端：暂停不提供持久会话保障。
  4. 忘记保存再运行程序：外部编译器读取的是磁盘文件，不一定能看到未保存的缓冲区内容。
  5. 混淆 :!cmd 和 :%!cmd：前者只执行，后者会用命令输出替换整个缓冲区。
  6. 忽略路径中的空格：脚本化命令应配合 shellescape() 和 expand('%:p')。
