LaTeX 排版 03：图片、表格与代码清单

文章目录

写实验报告时，正文通常最先完成，最耗时间的却是“图片为什么跑到下一页”“表格为什么超出边界”“代码为什么挤成一团”。解决这些问题，需要分清内容、容器和页面安排三个层次：图片文件提供内容，figure 管理浮动位置和题注，页面宽度决定它能放多大。表格与代码也有相同的层次。

本文把原来零散的插图和 listings 备忘整理成一套报告排版流程。建议先读文档基础与中文排版，再按本文完成一张组合图、一张实验结果表、一段带编号的代码。公式、单位与引用的完整用法见公式与参考文献，练习工程和编译入口见学习路线。

1. 先选图片格式，再考虑缩放

PDF、PNG、JPEG 和 EPS 怎么选

曲线图、框图和带细文字的统计图，优先从绘图程序导出保留矢量对象的 PDF；照片通常适合 JPEG；截图、透明背景图和需要无损保存的像素图可以用 PNG。PDF 和 EPS 都可以包含矢量内容，也可以包着一张低分辨率位图，因此扩展名本身不能保证清晰。把模糊 PNG 转成 PDF，不会恢复原来没有的细节。

现在常见的 pdfLaTeX、XeLaTeX 和 LuaLaTeX 的 PDF 输出流程都能处理 PDF、PNG、JPEG。传统 latex → DVI → dvips 流程主要使用 EPS；某些现代环境会自动调用转换工具处理 EPS，但是否可用取决于驱动和发行版配置。为了便于换机器重编译，可以先将已有 EPS 转为 PDF，并把转换后的文件纳入工程，而不是默认每位使用者都有自动转换链。引擎与驱动支持的边界见 LaTeX graphics 官方指南。

图像的最终阅读效果还取决于放置尺寸。假如曲线图导出时字号为 10 pt，整张图缩到原来的三分之一，图内文字也随之缩小。准备图片时就按单栏或双栏的最终宽度设计，往往比在 LaTeX 里不断缩放更有效。导出后放大检查线条、字体和图例，再回到正常比例判断是否易读。

一般在局部容器里用 \linewidth：它表示当前位置可用的行宽，会随列表、分栏、minipage 等环境改变。\textwidth 通常表示正文版心总宽度；在双栏页面里，拿它给普通单栏图片定宽就可能越界。某些环境也会局部重设 \textwidth，所以不要把它当作永远不变的页面常量。练习时先用 width=\linewidth，确认边界后再决定是否缩小。两种长度和插图缩放的示例可对照 Learn LaTeX 插图课程。

图片位置为什么不完全服从源代码

figure 是浮动体。LaTeX 会兼顾本页剩余空间、正文比例和浮动体队列安排它的位置。[htbp] 给出允许放置的区域：h 是当前位置附近，t 是页顶，b 是页底，p 是专门的浮动页。它不是“必须按我列出的顺序尝试”的命令，更不保证图片紧跟在某一句话后面。加上 ! 会放宽部分浮动限制，但不能让放不下的图片凭空塞进页面。

遇到位置不理想，先检查图片是否过高、前面有没有滞留的大图、允许位置是否过少。通常保留 [htbp] 比到处写 [h] 容易得到稳定结果。float 宏包提供的 [H] 可以把内容固定在当前位置，但也可能制造大片空白，只在确实需要不浮动的局部内容时使用。章节结束必须排出前面图表时，可以用 \clearpage；它同时换页，不适合每张图后都加。浮动规则的进一步说明见 Learn LaTeX 浮动体补充。

图内居中使用 \centering，通常不再嵌套 center 环境，避免附带额外上下间距。题注应说明读者如何理解图，例如坐标、条件和主要比较内容；正文负责讨论结论。将 \label 放在 \caption 后面，因为题注命令先更新图编号，标签才能记住正确的值。

在封面中放一张局部图片

封面可以先用 titlepage 组织标题、插图和作者，不需要一开始就引入全页背景、绝对定位或 eso-pic。下面片段放在正文开头，导言区需加载 graphicx；图片仍使用前面约定的真实文件 images/response.pdf。它直接放在封面中，不放进会移动位置的 figure。

两处 \vfill 会分配页面剩余的竖直空间，让图与标题、作者保持呼吸感。这里使用局部图片，标题不压在复杂背景上，调整尺寸也容易。如果已经设置 \graphicspath{{images/}}，图片参数可以简写为 response.pdf；仍要确保该文件存在。需要学校或期刊封面时，优先遵循其模板，再逐项调整这类内容结构。

2. 用 subcaption 组织真正的子图

两个 minipage 可以让内容并排，但它们只是局部盒子，不会自动生成“图 1(a)、图 1(b)”的子图层级。如果在两个盒子里各放一个普通 \caption，可能得到两个独立图编号。需要主图题注、子图题注和分别引用时，使用 subcaption 的 subfigure 环境。subcaption 官方手册详细说明了这套计数与引用方式。

换成真实图片时，把 \fbox{...} 那一行替换为 \includegraphics[width=\linewidth]{...}。这里的 \linewidth 已经是子图自身宽度。两块各占外层的 47%，给间距留下余量；如果写成两个 50% 再加固定间距，总宽度很容易超出一行。[t] 是盒子顶部对齐方式，与 figure 的浮动选项是两件事。

主图和子图各自有题注与标签。删除某个 \caption 会改变它的编号语义，不能简单认为“去掉标题文字就没有其他影响”。期刊模板可能已经提供或限制子图宏包，采用模板时先检查其说明，避免再加载旧 subfigure 宏包与 subcaption 混用。

3. 表格先安排信息，再选列类型

table 管理浮动和题注，tabular 管理行列。只有 tabular 也能显示表格，但不会自动获得表题和浮动行为。表格里的 & 分隔单元格，\\ 结束一行；普通文本中的 & 需要写成 \&。

booktabs 三线表与数字对齐

三线表不是“只能有三条横线”的机械要求，而是让表头、主体和分组清楚。booktabs 的 \toprule、\midrule、\bottomrule 管理线粗与周围留白，分组表头可以加 \cmidrule。通常不加竖线，把单位写进表头，读者会更容易沿列比较。booktabs 官方手册给出了这类正式表格的设计原则。

l、c、r 是左、中、右对齐的普通列，不会按小数点对齐。siunitx 的 S 列会解析数值并对齐相应部分。table-format=1.3 为整数一位、小数三位预留空间；它主要描述版式容量，并不等于要求把所有数据舍入到三位小数。若有负值，要为符号预留空间，例如 table-format=-1.3。文字表头用花括号保护，避免被按数字解析。这些配置采用 siunitx v3 的接口，复杂的误差、指数和舍入需求请查 siunitx 官方手册的表格章节，不要混抄不同大版本的选项。

在正文中排量值时，siunitx v3 还提供 \qty{12.5}{\milli\second}，将数字与毫秒单位一起排版；仅排单位可用 \unit{\milli\second}。同一份报告应统一使用这套接口，避免手动插入空格造成单位间距不一致。

长文字用 tabularx，别把整表缩到看不清

普通 l 列会按自然宽度延伸。一列塞入整句话后，表格可能比页面还宽。固定宽度的 p{宽度} 可以换行；希望表格总宽度恰好等于当前行宽时，可以使用 tabularx，让 X 列分配剩余宽度。

X 默认类似可换行的 p 列；\raggedright 避免窄列里单词间被拉出很大空隙，\arraybackslash 恢复表格行末 \\ 的含义。@{} 去掉表格左右边缘的额外列间距。这套机制由 tabularx 官方文档说明。

排不下时，先缩短表头、统一单位、把解释搬到题注或正文，再考虑换行列、拆表和横向页面。\resizebox{\linewidth}{!}{...} 会连文字一起缩小，虽然能消除越界，却未必解决阅读问题。过长文件路径等不可断开的文本也可能超宽，不能指望 X 列替你在任意字符处断行。

需要彩色表头时，可在导言区用 \usepackage[table]{xcolor}，然后在表头行前写 \rowcolor{gray!10}；不要在已经加载 xcolor 后再用另一组选项重复加载，否则可能遇到选项冲突。浅背景配深文字通常比深色大面积铺底更便于打印，颜色之外仍应保留清楚的表头和分组关系。正式投稿时以模板要求为准，接口见 xcolor 官方手册。

4. 跨页表格交给 longtable

table 和普通 tabular 不能自动把一张表拆到多页。较长的参数表、实验日志和符号表，可以直接在正文放 longtable，不要再把它包进 table、minipage 或 resizebox。这些容器会妨碍跨页。longtable 也不适用于普通双栏模式，需要先规划单栏表格所在的部分。longtable 官方文档说明了它的页眉、页脚与输出机制限制。

\endfirsthead 前面定义第一页表头，\endhead 前的下一块定义续页表头，\endfoot 定义非末页页脚，\endlastfoot 定义末页页脚。先保留这四块结构，再增加数据行，比在分页之后手工复制一张表稳定。

默认在行与行之间分页，单个极高的单元格不会自动拆成上下两半。因此，不要把一页长的说明塞进同一个单元格。首次或修改列宽后，可能需要再次编译才能让各页列宽稳定；用 latexmk 可以自动处理必要的重复编译。

5. 代码清单从一套可靠样式开始

所有键值选项用逗号分隔：tabsize=4, 正确，tabsize=4; 不正确。同一个样式里多次设置 basicstyle 不会自动累加，后面的设置会覆盖前面的值。因此字体大小和字族应合并写为 basicstyle=\small\ttfamily；希望关键字既蓝又粗，则把 \color{...}\bfseries 放进同一个 keywordstyle。优先使用 \ttfamily、\bfseries 等声明，减少复制旧命令造成的混乱。

numbers=left 只负责显示行号，行号区需要边距；breaklines=true 允许长行折行，但折行后的显示不意味着源文件真的多了一行。columns=fullflexible 减少为了固定字符格而增加的间距，keepspaces=true 保留缩进。样式应让读者看清结构，不必把每种字符都染上鲜艳颜色。参数的完整定义见 listings 官方手册。

本示例明确只保证 ASCII 代码。中文正文使用 XeLaTeX，并不自动解决 listings 对所有 Unicode 代码内容的处理：中文注释、特殊符号和字体回退仍需单独验证。可以先让代码保持 ASCII，把中文解释写在清单前后；确实要在清单里保留中文时，再用当前引擎和字体做最小样例测试。

当报告包含多段带题注的代码时，可以在正文开头合适的位置加入 \lstlistoflistings，生成代码目录。先给代码设置 caption，再让构建工具完成必要的重跑；不要手工维护清单编号。自定义语言与多组关键词强调属于更深入的样式配置，先把本文的基础样式用稳，再按 listings 手册扩展。

什么时候考虑 minted

minted 借助 Pygments 进行语法高亮，支持的语言与词法分析能力适合更复杂的代码展示。当前 v3 通过 latexminted 外部程序工作，依赖的 Python 组件通常由相应 TeX 安装方式提供。支持该程序的新版发行版可以通过受限 shell escape 运行，不应把“所有 minted 文档都必须加 -shell-escape”当作通用结论；旧版与不同打包方式可能有不同要求。先核对本机版本、可执行程序和官方安装说明，再决定编译配置。minted 官方手册记录了 v2/v3 的迁移差异。

本系列的基础工程使用 listings，便于先掌握代码清单的标题、引用与宽度控制。换用 minted 时，先在独立小文档验证依赖链，成功后再合入报告模板。

6. 从日志症状定位问题

排版异常时，每次只改一个因素：先做一个最小文档，只保留相关宏包和出问题的图表；确认它能编译，再逐步放回原工程。不要同时换引擎、模板和五个宏包，否则很难知道哪一步解决了问题。

症状 优先检查 修正方向
File ... not found 相对路径、大小写、文件是否跟源码一起保存 从主文件编译位置核对路径，避免使用个人电脑绝对路径
图片只剩边框或文件名 文档类、graphicx 是否开启 draft 最终构建关闭草稿图像模式
图号引用成节号 \label 是否在 \caption 之前 把标签移到题注后，再重新编译
引用显示 ?? 标签是否拼错、重复、缺少再次编译 检查日志的 undefined references，并用 latexmk 重建
Overfull \hbox 图片总宽、不可断文本、表格列宽、代码长行 缩短内容或调整局部结构，查看 PDF 中具体越界位置
表格出现 Extra alignment tab 本行 & 数量是否与列数一致 数清单元格，普通文本中的 & 改成 \&
Misplaced \noalign \midrule 前一行是否缺少 \\ 修正行结束位置，而不是删除横线
子图掉到下一行 两个盒子、空格和间距之和是否超宽 降低盒子宽度，检查是否插入了空白段落
跨页表格没有跨页 是否套了浮动体或盒子，是否启用双栏 让 longtable 直接处于可分页的单栏正文
代码样式后半段突然变化 是否重复定义了同一个键，是否少逗号 集中定义样式，局部只覆盖确实需要改变的键

日志没有错误只说明 TeX 完成了工作，不能代替阅读 PDF。最终还要检查图片文字是否过小、同类图尺寸是否一致、表格单位是否齐全、题注是否能独立理解，以及正文里是否真的解释了每一张图表。

7. 一次实验报告练习

先下载完整练习工程，也可以浏览主文件与参考 PDF。在仓库根目录按学习路线准备 Docker 环境后编译：

不要一次复制所有高级选项，依次完成以下练习，每一步都保存一份能编译的版本。

  1. 单图与引用。 放入自己导出的响应曲线，用 \caption 说明输入、时间范围和单位，在正文用 \ref 引用。验收时调整图的位置，正文中的编号仍应正确，不要手写“图 1”。
  2. 组合图。 把位置响应和控制输入合成两个子图，分别引用子图，再引用总图。把其中一个题注改成长句，检查两块是否仍在同一行、图像比例是否一致。
  3. 结果表。 写三种方法的误差和运行时间，使用 booktabs 与 S 列。再加入一个负数和一个两位整数，观察 table-format 是否需要调整。数值均可自拟，但题注要说明是练习数据。
  4. 文字表与跨页表。 把方法说明改为 X 列，确保自然换行。另建一张足够长的 longtable，检查第二页是否重复表头、最后一页是否没有“下页续”的提示。
  5. 代码清单。 导入一份十几行的 ASCII 程序，添加标题、标签和行号。故意把一行变长，确认发生的是显示折行，原程序的语义和缩进没有被改写。
  6. 主动排错。 在练习副本中把标签移到题注前，或在表格行末删掉一个 \\，观察错误。记录“症状—原因—修复”，随后恢复到干净编译状态。

完成后留下源文件、图片、代码和最终 PDF，避免只保存 PDF。下次写报告时复用的是结构与样式，而不是重新从聊天记录拼接选项。返回 LaTeX 排版分类可以继续安排公式、文献和完整文档练习。
